# Q5 Optimal

Sistema d'estudi orientat a 10/10 i matrícula d'honor.

## Principi central

No mesurem progrés per hores estudiades, sinó per **competències demostrades**.

Flux de cada tema:

`Backlog -> This Sprint -> Learning -> Practice -> Retrieval -> Exam Ready -> Done`

## Regles del sistema

1. **Retrieval abans de relectura.** Intenta recordar, explicar o implementar abans d'obrir apunts.
2. **Mastery Gate obligatòria.** Cap targeta passa a `Exam Ready` sense una prova observable.
3. **Feedback immediat.** Cada error important entra a `ERROR_LOG.md`.
4. **Spacing.** Els conceptes importants es tornen a recuperar després d'intervals creixents.
5. **Interleaving.** Quan un patró ja està après, es barreja amb altres patrons similars.
6. **Exam simulation.** Per validar mastery: sense apunts, ChatGPT ni ajudes que no existirien a l'examen.
7. **WIP limit.** Màxim 5 targetes simultànies entre `Learning` i `Practice`.
8. **Sprint setmanal.** Cada sprint prioritza el que té més retorn acadèmic, no una quota fixa d'hores.

## Criteri d'una bona targeta

Una targeta no diu "estudiar Java". Diu què has de poder fer.

Exemple:

> **PROP — Java OOP fluency**  
> Mastery Gate: crear des de zero un programa petit amb classes, constructors, encapsulació, herència, overriding, interface, `ArrayList` i `HashMap`, compilar-lo i explicar-lo sense consultar sintaxi.

## Sprint review

Al final de cada setmana:

1. Què podria entrar demà en un examen i encara em faria por?
2. On estic perdent punts realment?
3. Quina competència, si la domino aquesta setmana, té més retorn sobre la nota final?

Les respostes determinen el següent sprint.
